# Нативный обновлятор ArenaMP

[Лаунчер](../LAUNCHER_RU.md) · [Сборка](../BUILDING_RU.md)

## Назначение

Лаунчер читает манифест выбранной игровой сборки и проверяет обновления через `arena-updater`. Это нативное Qt/C++ приложение с отдельным окном этапов, прогресса и подробностей. Исходники: `apps/launcher/updatecontroller.cpp` и `apps/launcher/updater/arena_updater.cpp`.

В Windows загрузка использует WinHTTP и системную проверку сертификатов. В Linux используется Qt Network. TLS-зависимости других частей лаунчера рассматриваются отдельно от транспорта обновлятора.

## Манифест сборки

`build.ini` находится у выбранной сборки данных. Пример адресов — шаблон, который владелец должен заменить своими:

```ini
[Build]
format=1
name="My ArenaMP server"
data-path="Data Files"
complete=true
version=00001
build=00001
url="https://example.invalid/arenamp/"
url_check="https://example.invalid/arenamp/check.ini"
url_update="https://example.invalid/arenamp/content.zip"
url_win="https://example.invalid/arenamp/windows.zip"
url_linux="https://example.invalid/arenamp/linux.tar.gz"

[Server]
address="127.0.0.1"
port="25565"
```

| Поле | Назначение |
|---|---|
| `format` | Версия формата манифеста |
| `version` | Счётчик контента |
| `build` | Счётчик клиента/движка |
| `url_check` | Адрес удалённого `check.ini` |
| `url_update` | ZIP контента для каталога данных |
| `url_win` | Пакет клиента Windows |
| `url_linux` | Пакет клиента Linux |

Удалённый `check.ini` сообщает целевые счётчики и хеши:

```ini
version=00002
build=00002
# Добавьте действительные SHA-256 опубликованных файлов:
# sha256_update=<64 hex characters>
# sha256_win=<64 hex characters>
# sha256_linux=<64 hex characters>
```

Увеличивайте счётчик только после размещения соответствующего пакета. Хеш относится к точным байтам загружаемого архива. Не оставляйте шаблонный хеш как рабочее значение. Схема пакета должна соответствовать корню установленного клиента или контента.

## Порядок обновления

Лаунчер выполняет проверку доступности. При отсутствии настроенного URL или недоступности проверки исходники предусматривают сохранение возможности запуска игры. Доступное обновление переводит основное действие в состояние обновления.

Обновлятор загружает пакет во временное место, проверяет заданный SHA-256, подготавливает содержимое и применяет допустимые файлы после закрытия необходимых процессов. Во время применения файлов отмена ограничена, чтобы не прерывать замену посередине. Ошибки отражаются в окне и `Update.log`.

## Серверные данные

Политика `serverupdatepolicy.hpp` различает обновляемый серверный код, стартовые файлы и сохраняемое состояние владельца. Рабочие данные, конфигурация и обязательный манифест контента требуют сохранения. Действия обновлятора не заменяют внешние резервные копии.

Проверяйте обновление на копии установки с заполненными профилями, ячейками, пользовательской конфигурацией и мебелью. После обновления сверяйте их сохранность и версию скриптов.

## Связь с GitHub Releases

Workflow публикует собранные пакеты и SHA-256 в GitHub Releases. Чтобы клиент получал их из лаунчера, владелец отдельно указывает доступные URL в `build.ini` и размещает актуальный `check.ini`. Автоматическое создание релиза не редактирует манифест игрового проекта и не размещает принадлежащие ему данные Morrowind.

## Диагностика

Проверьте права записи, свободное место, доступность URL, полную комплектность обновлятора и соответствие хеша. Сохраните Update.log и точный адрес/счётчик пакета. Не заменяйте рабочую конфигурацию примером из документации.
